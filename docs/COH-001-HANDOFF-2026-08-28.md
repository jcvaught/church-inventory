## Risk and Rollback

- Main risk: An incorrect proposed permission policy could break legitimate
  church workflows if implemented without resolving the nine owner decisions.
- Compatibility concerns: The global store currently subscribes ordinary users
  to sensitive collections; restricting rules before client changes would
  produce denied listeners and possible loading/error regressions.
- Rollback procedure: This phase is documentation-only; revert the document
  commit if rejected. Any future rules rollout must retain a versioned prior
  rules commit and compatible client as documented in the model.
- Production actions still requiring approval: All inspection of live user/Auth
  state, backups, migration, rules deployment, callable deployment, production
  testing, and offboarding containment.

## Known Limitations

- This is a static authorization analysis, not a production account/session
  audit.
- It does not prove whether Firebase Auth users are disabled or tokens revoked
  when administrators mark profiles inactive.
- It deliberately does not resolve the nine product policy decisions.
- Paid-hub entitlement parity outside Jobs is identified but separated from the
  core confidentiality/operational authorization proposal.
- No emulator tests were added or run during this analysis-only phase.
