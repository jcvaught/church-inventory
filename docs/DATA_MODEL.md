# Firestore Data Model

All church data is namespaced under `churches/{churchId}/`. `churchId` is always `{creatorUid}-church` (set at church creation time).

## Collections

| Path | Contents |
|------|----------|
| `churches/{churchId}` | Church name, code, createdAt, createdBy (uid); `welcomeEmailSentAt` (set by `sendWelcomeEmail` CF for idempotency) |
| `churches/{churchId}/config/main` | Church metadata |
| `churches/{churchId}/config/settings` | `locations[]`, `ministries[]`, `tags[]`, `jobsRosterVisibility` (`'admin'`/`'signups'`/`'all'`, default `'signups'` — controls who can see signup names in Job Hub) |
| `churches/{churchId}/config/subscription` | Plan, hubs[], maxUsers, status (`active`/`trialing`/`past_due`/`canceled`), Stripe IDs, grandfathered; trial fields: `trialStartedAt`, `trialEndsAt`, `trialHubs[]`, `freeHubsSelected` (null during trial; string[] after expiry — auto-selected top-2 hubs by activity log), `trialWarningEmailSentAt` |
| `churches/{churchId}/items` | Equipment inventory items. Core: `itemId`, `description`, `location` (free-text, from `settings.locations`), `ministry`, `status`, `condition`, `tags[]`, `photoUrl`, `assignedTo`, financial fields. **Room-scoped inventory (Shape A, 2026-06-24):** optional `roomDocId` (FK → a `rooms` doc) + denormalized `roomName` — links an item to a reservable Space; powers the Inventory Space filter, the Manage-Spaces per-room item count, and the Phase 6 equipment-hold ⭐ match. Additive; coexists with free-text `location` (the full place-model convergence was deliberately deferred) |
| `churches/{churchId}/supplies` | Consumable supplies with quantity tracking |
| `churches/{churchId}/activityLog` | Immutable audit trail; client creates pin `performedBy`/`performedByName` to the authenticated user profile and use a server timestamp. `logActivity` derives the display name centrally from the one-shot authenticated profile with no fallback (DEC-2026-005), so malformed name-less profiles fail closed. Accepted limitation: an out-of-band name change can make a session's cached name stale and its audit writes fail until re-login; no current UI path changes names out of band. Historical rows may retain ISO-string timestamps; new rows use Firestore `Timestamp` values. |
| `churches/{churchId}/reservations` | Item and room/space reservation requests; `resourceType: 'item' \| 'room'` (absent on old records = treat as item); item fields: `itemDocId`, `itemId`, `itemDesc`; room fields: `roomDocId`, `roomName`, **`startTime`/`endTime`** (`"HH:MM"` 24h — room-calendar Phase 1, 2026-06-23; present ⇒ a single-day **timed** booking, absent/empty ⇒ all-day; multi-day spans stay all-day. Conflict detection is time-aware for rooms via `src/utils/reservationConflict.js`; the ICS feed emits timed VEVENTs. `setupMinutes`/`teardownMinutes` buffers are Phase 3 — the conflict engine already honors them, default 0); room booking detail (2026-06-23): `expectedAttendance` (nullable int — soft-warns when it exceeds the space's `capacity`, never blocks), `contactName`/`contactPhone` (day-of contact); shared: `eventName`, `eventDate`, `returnDate`, `purpose`, `ministry`, `notes`, `status`, `recurrenceGroupId`, `recurrenceFreq` |
| `churches/{churchId}/vendors` | Maintenance Hub: vendor/contractor directory |
| `churches/{churchId}/config/settings.maintenanceTags` | `string[]` — tag autocomplete for maintenance tickets; new tags added via `arrayUnion` |
| `churches/{churchId}/taskTemplates` | Tasks Hub: saved task templates; fields: `name`, `description`, `priority`, `tags[]`, `recurrence`, `checklist[{id,text,done}]`, `visibility`, `createdBy`, `createdByName`, `createdAt`; members read, admin+mgr write |
| `churches/{churchId}/rooms` | Spaces: reservable rooms/spaces; fields: `name`, `capacity` (nullable int), `location`, `description`, `amenities[]`, `active` (soft-archive), `createdAt`, `updatedAt`; **room-calendar best-practices fields (2026-06-23):** `photoUrl` (nullable; Storage `churches/{id}/rooms/<ts>`, reuses the item-photo upload + the existing `churches/{id}/**` storage rule), `approverUids[]` (uids who may approve bookings for THIS space, in addition to admins + the ministry manager — enforced UI-side in `ReservationsPage.canApproveReservation`), `blackoutDates[]` (`YYYY-MM-DD` the space is unavailable), `blockedWindows[]` (`{day:0-6, start:"HH:MM", end:"HH:MM", label}` weekly unavailable hours, e.g. Sunday service). Availability is enforced at booking time by `roomUnavailability()` in `src/utils/reservationConflict.js`; managed in Settings → Spaces card; members read, admin/mgr write |
| `churches/{churchId}/bundles` | Coordination Hub: checkout bundles; fields: `name`, `description`, `items[{docId,itemId,description,location}]`, `createdBy`, `createdByName`, `createdAt` |
| `churches/{churchId}/config/notifications` | Coordination Hub: notification toggle; fields: `enabled` (bool) — all email logic handled server-side via SendGrid Cloud Functions; legacy EmailJS fields (serviceId, publicKey, templateApproved, etc.) may exist in old docs but are no longer used |
| `churches/{churchId}/audits` | Accountability Hub: physical audit records; fields: `location`, `conductedBy`, `conductedByName`, `startedAt`, `completedAt`, `status`, `itemsChecked`, `discrepancyCount`, `items[{docId,itemId,description,currentStatus,auditResult,condition,notes}]`, `discrepancies[]`, `createdAt` |
| `churches/{churchId}/accessPeople` | People Access Hub: tracked people (staff/volunteers); fields: `name`, `email`, `phone`, `ministries[]`, `notes`, `active` (soft archive), `userId` (nullable — linked ChurchOpsHub user uid, set by auto-link or admin), `createdBy`, `createdAt`, `updatedAt`. Admins/managers may read all; ordinary members may read only docs whose `userId` is their own uid. |
| `churches/{churchId}/accessRecords` | People Access Hub: one flat collection for all compliance record types; fields: `personId`, `personName` (denormalized), `type` (`background_check`/`key_assignment`/`certification`/`custom`), `completedDate`, `expiryDate`, `notes`, `ministry`, `recordedBy`, `recordedByName`, `createdAt`, `updatedAt`; key_assignment adds: `keyIdentifier`, `returnedDate`; certification adds: `certType`, `issuingOrganization`; custom adds: `requirementId`, `requirementName`. Admins/managers may read all; ordinary members may read only records whose referenced `accessPeople` doc is linked to their uid. That self-read rule performs a parent `accessPeople` `get()` per evaluated record (same parent path is cacheable); the client bounds each self query to 100 records. |
| `churches/{churchId}/config/settings.peopleAccessRequirements` | `[{id, name, hasExpiry}]` — custom requirement types for People Access Hub; added via `arrayUnion` |
| `churches/{churchId}/jobListings` | Job Hub: posted jobs; fields: `jobNumber` (JOB-###), `title`, `description`, `scheduledDate`, `scheduledTime`, `location`, `spotsTotal`, `pay` (nullable float), `status` (`open`/`closed`/`completed`/`cancelled`), server-maintained `signupCount`/`waitlistCount` integers, `requiredAccessTypes[]`, `requiresWaiver`, `waiverText`, `createdBy`, `createdByName`, `createdAt`, `updatedAt`; recurring series: `recurrenceGroupId` (first job's docId, same for all siblings), `recurrenceFreq` (`weekly`/`biweekly`/`monthly`/`quarterly`/`annually`), `seriesEndDate` (YYYY-MM-DD); notification markers: `lastReminderSentDate`, `lastSmsReminderSentDate`, `cancellationEmailSentAt`, `lastPosterNotifiedByActors` (30s double-fire guard), `newJobsDigestSent` (bool — set once a job has been announced in the noon new-shift SMS digest; the one-time `scripts/prime-newjobs-digest.cjs` stamps the pre-today backlog so day-one doesn't blast volunteers). **Roster moved off the parent (audit H1, 2026-05-22):** signups/waitlist live in protected per-uid subcollections `jobListings/{id}/signups/{uid}` `{uid,name,signedUpAt,attended?,acknowledgedWaiverAt?}` and `…/waitlist/{uid}` `{uid,name,addedAt,acknowledgedWaiverAt?}`, written exclusively by the `jobSignUp`/`jobWithdraw`/`jobSetAttendance`/`promoteFromWaitlist` Cloud Functions (Admin SDK, compliance + waiver + capacity enforced server-side) |
| `churches/{churchId}/jobSwapRequests` | Job Hub: member-submitted replacement requests; fields: `jobDocId`, `uid`, `name`, `note` (≤1000 chars), `createdAt`; create is rule-bounded — exact key allowlist, `uid` pinned to the caller, `name` pinned to the caller's user-doc name (audit L4); admins read + dismiss; cleaned up when the job is deleted |
| `churches/{churchId}/jobAnnouncements` | Job Hub: announcements; fields: `title`, `body`, `expiresAt` (nullable YYYY-MM-DD, client-side filtered), `pinned` (bool), `createdBy`, `createdByName`, `createdAt`, `updatedAt` |
| `churches/{churchId}/publicRequests` | Public item requests submitted via `PublicRequestPage`; **unauthenticated creates allowed** (Firestore rule); fields: `name`, `email`, `phone`, `itemDescription`, `quantity`, `dateNeeded`, `urgency` (Low/Medium/High), `notes`, `status` (`pending`/`dismissed`), `submittedAt`; admins see pending requests in ItemsPage panel; dismissed via `dismissPublicRequest()` |
| `users/{uid}` | User profile with `churchId`, `role` (`admin`/`manager`/`user`), `name`, `email`, `active`, `allowedHubs[]`, `managedMinistries[]`, `taskDefaultVisibility` (`team`/`private`/`shared`; when unset the built-in default is `private`), `taskDefaultSharedWith` (`[{uid,name}]`), `jobPosterDelegates` (`[{uid,name}]` — up to 5; users who receive poster notifications for jobs you've posted); SMS: `phone` (E.164, nullable), `smsRemindersEnabled` (bool), `smsNewJobsEnabled` (bool — separate opt-in for the noon new-shift digest; both SMS flags are self-set only, admins can't change another user's — TCPA, rule-pinned), `smsConsentAt` (ISO string — set when the user opts into SMS; a `twilioInbound` START re-opt-in only revives accounts that carry it — audit M6) |
| `suggestions/{docId}` | **Top-level** (not church-scoped) — cross-church user suggestions; fields: `text`, `category`, `submittedBy`, `submittedByName`, `churchId`, `churchName`, `submittedAt` |
| `errors/{docId}` | **Top-level** — **unused.** Error telemetry is handled by Sentry (`handleErr()` in `useFirestore` calls `Sentry.captureException`, not a Firestore write — changed 2026-05-12). The Firestore rule denies all access (`allow read, write: if false`, audit M5) so any future use is a deliberate, considered change rather than a silent default |
| `scheduledJobRuns/{jobName}` | **Top-level** — per-run heartbeat for scheduled Cloud Functions (audit 2026-05-23 obs-H1). Single doc per scheduled job, overwritten each run by `withScheduledRun(name, fn)` (`functions/index.js`). Fields: `jobName`, `status` (`running`/`completed`/`failed`), `startedAt`, `finishedAt`, `durationMs`, `lastError` (nullable), `lastSummary` (optional `{processed}` for jobs that return one). Written by Cloud Functions only (Admin SDK bypasses rules). Use as the dead-man's switch input for a Cloud Monitoring alert when `finishedAt` goes stale |
| `churches/{churchId}/shepherdPeople/{pcoPersonId}` | **Shepherd Hub** (FXCC-only): Cloud-Function-synced, minimized read-only mirror of Planning Center people (`syncShepherdPeople` nightly + `refreshShepherdPeople` on-demand). Doc id = PCO person id. Fields: identity (`pcoId`, `firstName`, `lastName`, `nickname`, `name`, `avatarUrl`, `birthdate`, `anniversary`, `gender`, `child`); **status — copied verbatim from PCO**: `status` (`active`/`inactive`), `membership` (PCO type, e.g. Member/Regular Attender/Visitor — *separate field* from status), `directoryStatus`, `inactivatedAt`; contact arrays `emails[{address,location,primary}]`/`phones[]`/`addresses[]`; sensitive `medicalNotes`; `pastoral{elderAssigned (raw PCO value), dateBaptized, growthGroupMember, discipleship, strengths[], gifts[]}`; derived index `elderKeys[]` (normalized current-elder keys), `orphaned`, `hasAssignment`; `syncGeneration`, `updatedAt`. Admin-SDK-write-only |
| `churches/{churchId}/shepherdPeople/{id}/privateNotes/{ownerUid}` | **Shepherd Hub**: an elder's private note on a person; doc id = the elder's uid. Fields: `text`, `authorName`, `updatedAt`. Owner-only read+write (private even from other elders + admins) |
| `churches/{churchId}/shepherdPeople/{id}/careThread/{entryId}` | **Shepherd Hub**: shared care thread; fields: `text`, `authorUid`, `authorName`, `createdAt`. Any elder reads/appends; author-owned edit/delete |
| `churches/{churchId}/shepherdAudit/{entryId}` | **Shepherd Hub**: append-only audit log; fields: `action` (`view_person`/`edit_private_note`/`append_care`/`delete_care`/`reassign`), `personId`, `personName`, `actorUid`, `actorName`, `actorEmail`, `at`, `detail` (e.g. `{from,to}` for reassign) |
| `churches/{churchId}/config/shepherdRoster` | **Shepherd Hub**: editable elder roster (single source for the claim grant + PCO name-matching + roster UI). Fields: `elders[{key,name,surname,emails[],match[],active,sabbatical}]`, `former[{key,match[]}]`. Seeded from `functions/lib/roster.js` DEFAULT_ROSTER. Read elder/John; write John only |
| `churches/{churchId}/config/shepherdSync` | **Shepherd Hub**: sync status doc; `{lastSyncAt, source, totalFetched, stored, deleted, assigned, orphaned, perElderLoad{}, unmappedValues[], fieldDefs{}}`. Admin-SDK-write-only |

## Firestore Rules Summary

Granular per-subcollection rules (no wildcard). All church-scoped membership checks reject profiles with explicit `active:false`; missing `active` defaults to true for legacy profiles. Key constraints:

- `config/subscription` — client create only at church creation time; no client updates (webhook/Admin SDK only)
- `activityLog` — immutable; active members can create only with their own uid/profile name and `request.time`, and nobody can update or delete
- `accessPeople` / `accessRecords` — admins/managers can read the full hub; ordinary members can read only their linked person document(s) and those people's compliance records; writes remain admin/manager-only
- `workItems` / `workItems/comments` are the canonical Tasks and Maintenance paths; the four obsolete `tasks`/`tasks/comments`/`maintenanceTickets`/`maintenanceTickets/comments` rule blocks were removed, while `taskTemplates` remains supported
- `jobListings` — gated by `canUseJobsHub` (membership + active Jobs Hub subscription + per-user `allowedHubs`); update can't touch the roster counters, identity, recurrence, or notification stamps; the `signups`/`waitlist` subcollections are Cloud-Function-write-only, read per `canSeeJobRoster` (the `jobsRosterVisibility` setting); `jobAnnouncements` update can't rewrite `createdBy`/`createdByName`/`createdAt`; `jobSwapRequests` create is key-allowlisted with `uid`/`name` pinned and `note` ≤1000 chars
- `publicRequests` — unauthenticated create allowed but bounded (exact key allowlist + length caps); `errors` denies all access (unused — see table above)
- **Shepherd Hub** — all reads gated to `isElder()` (the server-set `elder` custom claim) or `isShepherdAdmin()` (John's email only via `OWNER_EMAILS`, NOT any church admin — pastoral data is need-to-know). `shepherdPeople` + `config/shepherdSync` are Cloud-Function-write-only (`write: if false`). `config/shepherdRoster` write = John only. `privateNotes/{ownerUid}` read+write = the owning elder only (`request.auth.uid == ownerUid`). `careThread` create/edit/delete = author-owned (`authorUid == request.auth.uid`, can't be forged). `shepherdAudit` is append-only (`update,delete: if false`), actor-stamped on create. The hub itself is FXCC-only + surfaced as a non-subscription "special" card in HubsPage (no UpgradeGate)
- Users cannot self-escalate role: create requires `role == 'user'`; self-updates cannot change `role`, `churchId`, `active`, or `allowedHubs`
- Storage rules enforce 5MB max upload size and `image/*` content type only
