## Scope delivered

1. **Active membership predicate.** `isMember` rejects an explicit
   `active:false`. Per the approved refinement at `3dda1f0`, legacy profiles
   without the field remain admitted via
   `userData().get('active', true) == true`. The Stage 0 production-field check
   is therefore an optional confirmation, not a gate.
2. **People Access containment.** Admins/managers retain full reads. Ordinary
   members may read only `accessPeople` docs linked to their uid and
   `accessRecords` whose referenced person doc is linked to their uid. The
   client no longer opens the three full People Access listeners for ordinary
   users; it queries their linked person docs and records only. Settings → My
   Compliance consumes those scoped arrays and is self-only.
3. **Trusted activity attribution.** Activity creates pin `performedBy` to the
   authenticated uid, `performedByName` to the user profile name, and
   `timestamp` to `request.time`, following the `shepherdAudit` pattern. Client
   writes use `serverTimestamp()`. Read and analytics paths normalize both new
   Firestore Timestamps and historical ISO strings during the compatibility
   period.
4. **Legacy rule removal.** Removed exactly the document and comment blocks for
   `tasks` and `maintenanceTickets`. `taskTemplates` and canonical `workItems`
   rules remain intact.

The branch history deliberately puts the role-aware client subscription change
before the restrictive rules change, preserving the required deployment order.
