## Findings

### MED-1 — `sendEmptyJobMorningAlert` has no per-day idempotency stamp (Brevo over-send risk)
`functions/index.js:2130-2203`. The function relies solely on the 7am hour-gate to fire once daily; it writes no per-church/per-day stamp (contrast `sendJobReminders`, which stamps `lastReminderSentDate`/`lastSmsReminderSentDate` and skips when both fired — `:2516-2522`). `onSchedule` is at-least-once and `withScheduledRun` is a heartbeat, not a dedup — a retry inside the 7am hour re-emails **all admins**. The f9bddf3 widening (`signupCount === 0` → `signupCount < spotsTotal`) makes it fire on nearly every partially-staffed Sunday, multiplying the church-days affected. Against the shared 300/day free Brevo cap (4 apps), this is a real over-send.
**Fix:** church-level stamp, e.g. `config/settings.lastEmptyJobAlertDate === todayStr → continue`, mirroring the reminder pattern.

### MED-2 — Client eligibility scans one tracked doc; server aggregates all (latent divergence)
`src/lib/people.js:233-234` filters `accessRecords` by the single `person.linkedTrackedId`; the server `isAccessEligible` (`functions/index.js:2926-2932`) aggregates a `Set` of **all** `accessPeople` docs whose `userId === uid`. The user↔tracked link is not DB-enforced as 1:1, so a uid linked to two tracked docs makes the Event-Day readiness badge (`shiftReadiness`) disagree with what `jobSignUp`/`promoteFromWaitlist` actually enforce. The parity suite only seeds 1:1 fixtures, so it stays green while the gap is live. Server is the authoritative gate → worst case is a misleading UI badge, not a bypass.
**Fix:** resolve client eligibility over *all* tracked ids for the user (mirror the server Set form), or enforce/validate the 1:1 link. The `people.js:228-229` comment already admits the asymmetry.

### MED-3 — ICS feed/download emits unfolded long lines (RFC 5545 §3.1 violation)
`src/lib/occurrences.js` + CJS twin `functions/lib/occurrences.js`: `occurrenceToVEvent`/`buildCalendar` emit `SUMMARY:`/`DESCRIPTION:`/`LOCATION:` verbatim. `escICS` escapes `\,;\n` but never folds at 75 octets. A long job/reservation title or description produces a >75-octet content line; strict importers (some Outlook/Exchange) reject or truncate. Affects both the `icsCalendarFeed` endpoint and the client `.ics` download (shared builder). Not a parity bug — client and server agree.
**Fix:** add a `foldLine()` (split at 75 octets, continuation lines prefixed with one space) in the shared `occurrences.js` and apply in `buildCalendar`.

### LOW-1 — `promoteWaitlistForJob`/`isAccessEligible` use UTC `toISOString` date (documented pitfall class)
`functions/index.js:2957` `const todayS = new Date().toISOString().slice(0,10)` — the exact UTC off-by-one CLAUDE.md's 🟡 pitfall warns against. Server runs UTC and has no church tz in this path, so a late-evening US sign-up promotion compares cert expiry against *tomorrow's* date — a record expiring "today" can be wrongly treated as expired (fail-closed → blocks a still-valid volunteer) on the boundary day only. Low impact; same pattern likely in the sibling `jobSignUp` path — worth a consistent sweep.

### LOW-2 — `seed-emulator.mjs` writes to dead `tasks`/`maintenanceTickets` collections
`scripts/seed-emulator.mjs:83,97` (+ comments `:87,100`, read-back `:131`). Same regression class as e1169cd, but **dev-tooling only, no prod impact**: the emulator seeder claims to seed "4 tasks · 3 maintenance" to fill the Kanban, but the WorkBoard reads `workItems`-only → local sandbox shows an empty Work board.
**Fix:** write to `workItems` with `task_`/`mnt_` prefixes + `type` discriminator, mirroring `addTask`/`addTicket`.

### LOW-3 — `computeAttention` sort uses locale-dependent `localeCompare` + `'￿'` sentinel
`src/lib/attention.js:244` (+ CJS `:164`): `(a.dueDate||'￿').localeCompare(b.dueDate||'￿')`. `localeCompare` with no explicit locale uses the runtime default, which can differ browser↔Node; a latent client/server reorder of identically-dated items (feeds both the dashboard render and the Claude digest prompt). ASCII `YYYY-MM-DD` is stable in practice → cosmetic.
**Fix:** plain `<`/`>` string compare with a `'~'` sentinel, matching the rest of the codebase.

### LOW-4 — `people.js` expiry helpers default `today = new Date()` (latent TZ dependence)
`src/lib/people.js:72,91,231,250`. Pure when callers inject `today` (all audited callers do), but the bare-default path uses local `new Date()` → client browser TZ vs server UTC disagree.
**Fix:** make `today`/`todayStr` a required arg to force the injection contract.

### LOW-5 — Dead `tasks.dueDate` field override left in `firestore.indexes.json`
`firestore.indexes.json:70-76`. Harmless leftover from the old `tasks` collection; remove on next index edit.
